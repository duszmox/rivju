# rivju — architecture decisions (settled)

rivju is an **Electron desktop app** for agentic review of GitLab merge requests.
It runs headless Claude Code agents on the user's machine against a local checkout
of an MR and collects structured review findings.

Every decision below is SETTLED. Do not revisit, redesign, or "improve" them.
If a decision appears wrong, implement it as written and note the concern in your
final report.

## Shell

- Electron app. Renderer is a **client-only React 19 SPA** (TanStack Router, memory
  history). No SSR.
- `@tanstack/react-start`, `nitro`, and `pg` are REMOVED from the project.
- All privileged work (GitLab API, git, claude subprocess, DB) happens in the
  **main process**. The renderer holds no business logic.
- Build: `electron-vite` v5 (`src/main/`, `src/preload/`, `src/renderer/`).
  Packaging: `electron-builder` 26.
- `contextIsolation: true`, `nodeIntegration: false`, no remote content loaded.

## IPC

- **tRPC v11** router in main, reached from the renderer through a small custom
  IPC link we own (~60 lines in preload + renderer). Do NOT add `electron-trpc`
  or any third-party IPC wrapper.
- Renderer uses **TanStack Query** over the tRPC client.
- Streaming run state is delivered by tRPC **subscriptions** backed by a
  main-process event bus (`run:*` events) over `webContents.send`.

## Persistence

- **SQLite** via `better-sqlite3` + `drizzle-orm/better-sqlite3`.
- DB file: `app.getPath('userData')/rivju.db`, WAL mode.
- Migrations generated by `drizzle-kit` into `drizzle/`, bundled as an app asset,
  applied with drizzle's `migrate()` on boot behind a version check.
- Native module rebuilt for Electron's ABI via `@electron/rebuild`.

## Claude agent invocation

- `@anthropic-ai/claude-agent-sdk` `query()` from the main process.
- **Credentials are inherited from the user's existing `claude` CLI login.** The
  app must require zero API key setup for a user who already runs `claude` in a
  terminal. An optional key override may live in settings.
- The app hard-depends on the `claude` binary. A startup **preflight** locates it
  (`PATH`, then `~/.local/bin`, then `~/.claude/local`), starts a throwaway SDK
  session, and captures `models: ModelInfo[]` and `account: AccountInfo` from the
  session init response. If it is missing or unauthenticated, show a blocking
  remediation screen.
- The model dropdown is populated from that live `ModelInfo[]` — **never hardcode
  a model list**. Effort options come from each model's `supportedEffortLevels`,
  gated by `supportsEffort`.

## Review skills

- Skills are real `SKILL.md` directories owned by the app, loaded as Claude Code
  **local plugins**:
  - user scope:    `<userData>/skills/user/`
  - project scope: `<userData>/skills/project/<instance-id>/<project-path>/`
- Passed to the SDK as `plugins: [{ type: 'local', path, skipMcpDiscovery: true }]`.
- Toggling on/off uses the SDK's native `skills: string[]` context filter — the
  array of enabled skill names. **Never move, rename, or delete files to
  implement a toggle.**
- `settingSources: []` so nothing from the user's real `~/.claude` leaks in.
- `SKILL.md` frontmatter contains ONLY standard keys (`name`, `description`).
  All rivju state (enabled, scope, order, origin) lives in SQLite, keyed by skill
  name. Never write custom frontmatter keys.
- Importing from a checkout's `.claude/skills/*` must `realpath` to resolve
  symlinks before copying.

## Output contract (NOT a skill)

Findings arrive exclusively as **validated MCP tool calls**, never as parsed prose
or JSON in text. An in-process SDK MCP server (`createSdkMcpServer` + `tool()`
with zod) exposes:

- `submit_finding` — one finding.
- `finish_review` — summary + confidence; closes the run.

The schema lives in the tool definition plus a fixed system prompt block. It is
always on, not toggleable, and not user-editable. Users may break their review
instructions; they must not be able to break the wire format.

### Server-side verification gate (critical)

`submit_finding` MUST reject a finding when:
- `file_path` does not exist at `head_sha`, or
- the quoted `anchor_snippet` does not match the file content at the claimed
  location.

The rejection is returned **as the tool result** so the agent self-corrects, and
recorded as a `finding_event`. Hallucinated line numbers are the primary
credibility risk for this product; this gate is what prevents them.

## Finding identity and re-anchoring

- A `finding` belongs to the **merge request**, never to a run. Runs attach
  evidence to findings.
- Identity: `fingerprint = sha256(file_path + normalized(anchor_snippet) + category)`.
  Deliberately EXCLUDES line numbers and the prose title.
- Each finding stores `anchor_snippet` (1-3 lines) plus 3 lines of context each side.
- Re-anchoring at a new head SHA: exact snippet match -> new line; multiple
  matches -> disambiguate using the context lines; zero matches -> `stale`
  (a signal, not proof of a fix).
- `scope` is `line` | `file` | `global`, so general observations are never forced
  into a fake line number.

## Two orthogonal state axes

- **Triage** (set by the human): `untriaged` | `valid` | `invalid` + free-text note.
- **Lifecycle** (set by the system): `open` | `fixed` | `stale` | `moot`.

These never overwrite each other.

## Runs

- `kind`: `full` (fresh review) or `verify` (targeted check of still-open findings).
  `verify` is the primary re-run button; `full` re-review is secondary and merges
  by fingerprint so existing triage survives.
- Global semaphore, default 2 concurrent runs, user-configurable, hard cap 5,
  with a visible queue.
- Per-run `AbortController` wired to the SDK; tree-kill the child process on
  `before-quit`.
- Any run still `running` at boot is marked `interrupted`. Never silently resumed.
- The full SDK message stream is written to `<userData>/logs/<run-id>.jsonl`
  (NOT SQLite). This is the primary debugging artifact.

## Repo access

- Never touch the user's own working tree.
- `git clone --mirror` into `<userData>/repos/<instance>/<project>.git`, using
  `--reference` against a user-supplied local clone when available.
- PAT for git auth is held **in memory only** (credential helper). Never written
  into `.git/config`.
- Per run: `git fetch` then `git worktree add --detach <path> <head_sha>`.
- Worktree removed on success; **retained on failure** for debugging, GC'd after
  24h. `git worktree prune` + orphan-directory sweep at boot.

## Agent capabilities

- `allowedTools`: `Read`, `Grep`, `Glob`, `Bash`, `Skill`,
  `mcp__rivju__submit_finding`, `mcp__rivju__finish_review`.
- **No `Write`, no `Edit`, no `WebFetch`.**
- `canUseTool` hard-denies anything mutating and allowlists Bash to read-only
  shapes: `git log|show|diff|blame`, `rg`, `ls`, `cat`, `sed -n`.
- Sandbox enabled with network denied.
- `maxTurns` cap plus a wall-clock timeout.
- `includePartialMessages: true` for live progress; `stderr` captured.

## Model and effort selection

Layered, resolved at run launch: **global default -> per-project override ->
per-run override** in the launch dialog. The resolved `model` and `effort` are
stored on the `run` row so every review records what produced it.

## Large merge requests

Do NOT chunk silently. Compute a size budget; above ~150 files or ~20k diff lines,
present the user a file picker to scope the review. Silent degradation destroys
trust in a review tool.

## GitLab

- **REST v4** (not GraphQL) — self-hosted instances span many GitLab versions and
  REST v4 is far more forgiving.
- Multiple self-hosted instances supported from day one.
- Personal access tokens, `api` scope requested.
- Tokens stored as `safeStorage.encryptString` ciphertext in SQLite. The plaintext
  token NEVER crosses IPC into the renderer. Guard
  `safeStorage.isEncryptionAvailable()` and refuse to store rather than silently
  downgrade to plaintext.
- On add: validate with `GET /api/v4/user` and `GET /api/v4/version`; capture
  username + version; warn below GitLab 15.
- Default MR filter: `reviewer_id=me` + `assignee_id=me`. Per-project browsing is
  a secondary view.
- **v1 is read-only.** Posting findings back to GitLab is a later phase.

## UI

- Left sidebar manages multiple concurrent/queued runs with a live phase and
  tool-call ticker, token + cost readout, and cancel.
- Diff rendering: `react-diff-view` + `gitdiff-parser`, with `shiki` for
  token-level highlighting, unified/split toggle, collapsed-context expansion.
- `line`-scoped findings render as inline widget cards at their anchor line.
  `file`/`global`-scoped findings render in a right-hand panel.
- Triage is keyboard-driven (`j`/`k`/`v`/`x`) with optimistic updates.

## Testing

- **Vitest** over the pure main-process layers: GitLab client against recorded
  fixtures, re-anchoring, fingerprinting, skill resolution, diff budgeting,
  and replay of recorded run JSONL into the parsing/verification layer.
- One Playwright-Electron smoke test: launch, add token, render.
- Do NOT attempt to unit-test the agent itself.

## Data model (SQLite)

```
gitlab_instance   id, label, base_url, token_ciphertext, token_scopes,
                  gitlab_version, user_id, username, created_at
project           id, instance_id, gitlab_project_id, path_with_namespace, name,
                  default_branch, mirror_path, reference_clone_path?,
                  model_override?, effort_override?
merge_request     id, project_id, iid, title, description, author, source_branch,
                  target_branch, state, web_url, updated_at, last_seen_head_sha
run               id, merge_request_id, kind('full'|'verify'), status('queued'|
                  'running'|'done'|'failed'|'cancelled'|'interrupted'),
                  base_sha, head_sha, model, effort, enabled_skills(json),
                  worktree_path, log_path, usage(json), error, started_at, ended_at
finding           id, merge_request_id, fingerprint (unique per MR),
                  scope('line'|'file'|'global'), file_path, anchor_snippet,
                  ctx_before, ctx_after, current_line, category, severity, title,
                  body, suggested_fix, created_run_id, first_seen_head_sha,
                  triage('untriaged'|'valid'|'invalid'), triage_note,
                  lifecycle('open'|'fixed'|'stale'|'moot'), lifecycle_run_id
finding_event     id, finding_id, run_id, type('submitted'|'rejected_by_verifier'|
                  'reanchored'|'verified'|'triaged'), payload(json), created_at
skill             id, scope('user'|'project'), project_id?, name, dir_path,
                  description, enabled, sort_order,
                  origin('builtin'|'user'|'imported')
setting           key, value
```
