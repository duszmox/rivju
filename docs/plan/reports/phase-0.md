# Phase 0 report — Skeleton, tRPC-over-IPC, SQLite, claude preflight

Status: complete (with one late fix, see "The ESM/CJS bug"). `npx tsc --noEmit`
and `npm run lint` pass; `npm run build` emits `out/main/index.cjs`,
`out/preload/index.cjs`, and the renderer bundle. `npm run dev` / `npm run dist`
were **not** run in the finishing session (long-running); the exit criteria that
depend on them still need a manual pass.

## What was built

Electron + electron-vite skeleton replacing the old TanStack Start/Nitro/Postgres
scaffold. Three build targets: `src/main` (main process, CJS), `src/preload`
(contextBridge, CJS), `src/renderer` (React SPA, ESM). TanStack Router with
memory history, TanStack Query + tRPC v11 with a hand-rolled IPC link,
better-sqlite3 + drizzle with the full data model migrated at boot, claude CLI
preflight with blocking remediation UI, and a dev-only fake streaming run that
proves the `run:*` pipeline end to end.

## tRPC-over-IPC, end to end

1. **Renderer** calls e.g. `trpc.system.ping.queryOptions()` (proxy) or
   `client.runs.watch.subscribe(...)` (raw client).
2. **`ipcLink()`** (`lib/trpc.tsx`) turns each op into a `window.rivju.invoke`
   or `window.rivju.subscribe` call with `{ id, type, path, input }`.
3. **Preload** (`contextBridge`) forwards to `ipcRenderer.invoke('rivju:trpc:invoke')`
   or, for subscriptions, generates a unique `replyChannel`
   (`rivju:trpc:sub:<id>:<uuid>`), registers a listener on it, and sends
   `rivju:trpc:subscribe`. The returned unsubscribe removes the listener and
   sends `rivju:trpc:unsubscribe`.
4. **Main** (`trpc/ipc.ts`) resolves the dotted `path` against the caller object
   segment by segment (`resolveProcedure`) and calls it.
   - invoke: one-shot promise → `{ id, result: { type: 'data', data } }` or
     `{ id, error }` (tRPC error shape via `getTRPCErrorFromUnknown` +
     `TRPC_ERROR_CODES_BY_KEY`).
   - subscribe: sends `started`, then iterates the async iterable returned by
     the procedure, sending one `data` envelope per chunk and `stopped` at the
     end. Each replyChannel gets an `AbortController`; unsubscribe or window
     destroy aborts it, which closes the main-side stream. Re-subscribing on the
     same channel aborts the previous one.
5. **Renderer link** forwards `data`/`started`/`stopped` chunks verbatim and
   converts `error` envelopes via `TRPCClientError.from(...)`. Envelope shapes
   were verified against @trpc/client 11.x internals.

**Adding a new router namespace (Phase 1+):** add a key to `appRouter` in
`src/main/trpc/router.ts` (e.g. `gitlab: { listInstances: publicProcedure.query(...) }`).
Nothing else needs wiring — the IPC transport resolves paths dynamically, and
the renderer gets full type safety because `lib/trpc.tsx` imports `AppRouter`
as a *type* directly from `src/main/trpc/router.ts` (type-only import, erased at
build). If procedures need main-process state beyond `db`, extend
`TrpcContext` in `trpc/context.ts` (context is currently created in
`index.ts` and passed to `createCaller`).

## runs.watch and the event bus

- `events/bus.ts` is a plain in-process `Set<Listener>`; main-process code
  (currently only `runs/fake.ts`) calls `emitRunEvent()` with a typed `RunEvent`.
- `runEventStream()` creates an independent per-subscriber queue (no fan-out
  backpressure concerns at this scale; events are small). A pending `next()`
  parks on a `wake` promise; `close()` resolves it as done, which is what ends
  the `for await` in the subscription.
- `runs.watch` in the router is an async generator: it creates a stream, closes
  it on the tRPC abort signal, and yields events as they arrive.
- The renderer mounts **one** subscription for the whole app (`RunsProvider`),
  and all run state is derived from the stream — there is no per-run polling.
- Note: the stream is live-only. Events emitted before a subscriber connects are
  gone; there is no replay. Fine for Phase 0; a Phase 3 run engine will likely
  want a "snapshot current state, then stream" pattern.

## Database

- File location: `app.getPath('userData')/rivju.db` → on macOS
  `~/Library/Application Support/rivju/rivju.db`. WAL mode, foreign keys on.
- `db/client.ts` is a singleton; `openDatabase` runs once in `index.ts` boot.
- `db/migrate.ts` applies drizzle migrations at boot from the migrations folder:
  dev → `<repo>/drizzle` (resolved relative to the bundled main at
  `out/main/…`), packaged → `Resources/drizzle` (electron-builder
  `extraResources` copies the folder). A journal-hash stamp in the `setting`
  table makes the common case a no-op; `migrate()` itself is idempotent, so the
  stamp is an optimization, not correctness.
- Migrations are generated with `npm run db:generate` (drizzle-kit, config in
  `drizzle.config.ts`); the initial `0000_high_wraith.sql` exists under
  `drizzle/`. drizzle-kit's own CLI runs use a scratch db (`.rivju-cli.db` at
  the repo root) — that file is a dev artifact, not the app's db.
- `interruptStaleRuns` runs after migration at every boot.

## Claude preflight

- **Binary location** (`locateClaudeBinary`): every dir on `PATH`, then
  `~/.local/bin/claude`, then `~/.claude/local/claude` — order fixed by
  00-architecture.md. First candidate passing `accessSync(X_OK)` wins.
- **Probe** (`runPreflight`): a throwaway SDK `query()` session in a fresh
  mkdtemp cwd — `settingSources: []` (the user's real `~/.claude` settings are
  not loaded; auth is inherited from their existing CLI login), no allowed
  tools, `maxTurns: 1`, 45 s abort timeout. Captures `account` + `models` from
  `initializationResult()`, then interrupts/closes the session.
- **Caching** (`setting` table keys): `claude.models` (JSON), `claude.account`
  (JSON), `claude.claude_path`, `claude.checked_at`. Written on every successful
  probe; `loadCachedPreflight()` seeds an `ok, fromCache: true` state at boot so
  the app is usable instantly while the live check re-runs and replaces it.
- **Failures** are classified into `binary-not-found`, `not-authenticated`
  (regex on the error message), `timeout` (AbortError), or `session-failed`,
  each with a user-facing hint. The renderer blocks on this via
  `PreflightGate`; retry is a `system.preflightRetry` mutation.

## The ESM/CJS bug (fixed in this session)

`npm run dev` crashed at startup: package.json has `"type": "module"`, so the
bundled `out/main/index.js` was loaded as ESM, and named imports from
Electron's CommonJS built-in `electron` module fail
(`does not provide an export named 'BrowserWindow'`). Fix:

- `electron.vite.config.ts`: both `main` and `preload` rollup output set to
  `format: 'cjs'` with `entryFileNames: '[name].cjs'` (and matching
  `chunkFileNames`). Renderer stays ESM.
- `package.json`: `"main": "out/main/index.cjs"`.
- `src/main/window.ts`: preload path is now `out/preload/index.cjs`.
- `src/main/window.ts` and `src/main/paths.ts`: `import.meta.dirname` replaced
  with `__dirname` — `import.meta` is invalid in a CJS bundle and would have
  broken path resolution at runtime. tsconfig still says `module: ESNext`;
  `__dirname` typechecks via @types/node and is correct only because the output
  is CJS — don't flip the build back to ESM without revisiting these.
- Verified: `npx tsc --noEmit`, `npm run lint`, `npm run build` all pass;
  `out/main/index.cjs` and `out/preload/index.cjs` exist and start with
  `"use strict"` / `require("electron")`.

## Known deviations and rough edges

1. **Nothing is committed** — the repo has zero commits; per AGENTS.md the work
   stays in the working tree. The phase brief's "commit the initial migration
   files" was interpreted as "generate them" (`drizzle/0000_high_wraith.sql`
   exists).
2. **`npm run dist` not verified in this session** (heavy; deliberately
   skipped). The phase brief makes a successful mac dist an exit criterion —
   it still needs a manual run. The `asarUnpack` + `@electron/rebuild` +
   `postinstall` wiring for better-sqlite3 is in place, and the native module
   is marked external in the main bundle.
3. **`sandbox: false`** in the window. Kept so the preload can use Node APIs
   later if needed; `contextIsolation: true` and `nodeIntegration: false` are
   the actual security boundary, and the bridge surface is only
   `invoke`/`subscribe`. Could be revisited (a CJS preload is sandbox-friendly
   if it stays to the electron subset).
4. **Renderer bundle is ~1 MB** (999 kB JS, no manual chunks). Fine for a
   desktop app; not worth optimizing in Phase 0.
5. **Fake-run usage numbers are synthetic** and priced at a hardcoded
   $3/M input + $15/M output. Phase 3 replaces this with real SDK usage.
6. **`resolveProcedure` walks plain object properties** — there is no zod
   validation of the IPC *request envelope* itself (path/input are trusted
   shapes). Unknown paths throw tRPC `NOT_FOUND`, which is safe, but if we ever
   expose richer input, remember plan rule 3: zod at every boundary.
7. **`runs.watch` has no replay/snapshot** (see above) — Phase 3's engine
   should add a state snapshot procedure alongside the stream.
8. **`tsconfig.json` includes both main and renderer** with DOM libs and
   `module: ESNext`; it works (thanks to `verbatimModuleSyntax` + skipLibCheck)
   but there is no separate tsconfig per build target. If main-process code
   ever needs Node-only lib settings, split it.
9. **Preflight runs unconditionally at every boot** even with a fresh cache —
   that is by design (cache is only a boot-time seed), but it means a 1–3 s
   claude session on every launch.

## Packaged preflight fix (post-Phase-0 session)

**Root cause.** The packaged app failed preflight with `spawn ENOTDIR` while dev
worked. `claude/preflight.ts` called the SDK's `query()` without
`pathToClaudeCodeExecutable`, so the Agent SDK fell back to its bundled
platform binary (`@anthropic-ai/claude-agent-sdk-darwin-arm64/claude`) resolved
relative to the SDK module's own location. In the packaged app that location is
inside `app.asar`; since an asar archive is a single file, `app.asar` as a path
component is a file, not a directory, and `spawn` fails with ENOTDIR.
electron-builder had unpacked the real binary to `app.asar.unpacked/…`, but the
SDK does not know to rewrite the path.

**Fix.**

- New `src/main/claude/executable.ts` exports `resolveClaudeExecutable()` —
  the one place every SDK session gets its executable from. Resolution order:
  the user's installed binary via the existing search (`PATH`, `~/.local/bin`,
  `~/.claude/local`, moved here from preflight as `locateClaudeBinary()`),
  then the SDK's bundled platform binary as fallback. When `app.isPackaged`,
  the bundled path is rewritten segment-wise from `app.asar` to
  `app.asar.unpacked` so the spawn targets a real file on disk.
- `runPreflight()` resolves once via the helper and threads the path into
  `probeSession()`, which now passes `pathToClaudeCodeExecutable` to `query()`.
- `package.json` `asarUnpack` gains
  `node_modules/@anthropic-ai/claude-agent-sdk-*/**` (alongside `**/*.node`) so
  the bundled fallback binary is reliably on disk.
- The `binary-not-found` failure now names where rivju looked and tells the
  user to install Claude Code.

**Rule for future phases (Phase 3 especially).** Never call the SDK `query()`
without `pathToClaudeCodeExecutable`. Import `resolveClaudeExecutable()` from
`src/main/claude/executable.ts` and pass its result in the options. The helper
prefers the user's installed CLI (rivju inherits their CLI login — the
architecture's hard dependency) and only falls back to the SDK's bundled
binary if that is missing. Relying on the SDK's own resolution breaks every
packaged build with ENOTDIR.

Verified with `npx tsc --noEmit`, `npm run lint`, `npm run build` (this
session); `npm run dev` / `npm run dist` deliberately not run (long-running —
manual pass still owed, see "Known deviations" #2).

## What Phase 1 (GitLab integration) needs to know

- **Token storage**: `gitlab_instance.token_ciphertext` already exists in the
  schema (`safeStorage` ciphertext, comment in schema.ts). Phase 1 implements
  the vault (`src/main/security/tokens.ts`); nothing in Phase 0 touches
  `safeStorage` yet. Guard `isEncryptionAvailable()` and never return plaintext
  from any procedure.
- **Extending tRPC**: add a `gitlab` namespace to `appRouter`; no transport
  changes needed (see "Adding a new router namespace" above). Extend
  `TrpcContext` in `trpc/context.ts` if the client needs paths/instances —
  context is constructed once in `src/main/index.ts`.
- **zod**: the transport passes raw input (`unknown`) to procedures; validate
  inputs in the procedures themselves (router already does this for
  `fakeCancel` — copy that pattern).
- **MR list is live-fetched** (TanStack Query, 60 s staleTime) — do not turn it
  into a tRPC subscription; plain queries through the existing proxy are the
  intended pattern. `schema.ts` rows (`project`, `merge_request`) are for
  caching/persistence, not the source of truth for lists.
- **Migrations**: any schema change goes through `npm run db:generate` and lands
  as a new file in `drizzle/`; boot migration picks it up automatically. The
  journal-hash stamp handles the rest.
- **Renderer patterns to reuse**: `PreflightGate` (blocking gate + retry
  mutation) is the template for any connect/validate flow; the sidebar's
  `useQuery(trpc.x.y.queryOptions())` usage is the idiomatic read path.
- **UI tokens**: use the existing CSS variables from `styles.css`
  (`--sea-ink`, `--foam`, `--lagoon-deep`, `--palm`, `--line`, `--surface`)
  rather than raw colors.
